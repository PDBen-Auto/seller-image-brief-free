# 卖家图片策划 Free

把一个产品的真实资料和用户提供的评论，转成可以交给设计师和摄影师的三张图片任务单。免费版完成最多三张、各回答不同购买问题的小方案；资料不足时减少，不为图数凑重复内容。不声称图片已经制作或转化率已提升。

## Implementation Basis and Dependencies

基于提供的产品事实、评论内容和 FABE（特征、优势、用户利益、支持证据）逐图推导。需要能够读取文本/CSV/表格的 Agent 与可用模型，用户自备运行环境和可能产生的模型费用；不需要外部账号、API 或联网。表格读取工具缺失时请用户提供可读文本或 CSV。没有评论时仍可基于产品资料制作明确标记为假设的初稿。准确的公开商品声明还需要产品证据及当前平台规则核验。

## Inputs

- `product`：必需，文本或文件，含产品类别、版本、面向市场及已确认的功能或配件；例“收纳盒，黑色，带隔板”。缺少决定核心画面的事实时询问，否则写未知。勿要求密码或客户个人资料。
- `reviews`：可选，用户有权使用的文本、CSV 或表格，包含评论内容，最好有来源 ID、日期及适用 SKU；空文件或不可读时说明并仅输出产品假设。不推断无证据的占比，不把单条当整体。
- `proof`：可选，照片、尺寸、测试或产品文档；无证据的性能、适配、安全、认证、产品构成写“待验证”，不用作已确认卖点。
- `market_and_format`：可选，站点、语言、图数和画幅；默认美国站，最多三图、中文需求及必要英文示例；未核对当前平台规则时不得称可直接上架。
- `upgrade_notice`：可选，默认开启；用户说“不推荐升级/关闭升级提示”时关闭。若运行环境允许读取环境变量，仅读取 `SELLER_IMAGE_NO_UPSELL`，值为 `1` 时关闭；无法读取时不声称已检查该设置，用户仍可在对话中关闭。任何模式下不联网、不记录使用数据。

## Outputs

默认在对话中输出，用户要求文件时写入用户指定目录，格式为 Markdown。输出：输入范围和证据 ID；买家关注点及其证据或假设；最多三条职责不同的图卡；每条包含买家问题、F/A/B/E、画面布局、拍摄对象与角度、短文案、证据状态；最后列待验证事项。不能读取资料时给部分结果并列缺口，不虚构图片、原文或评论统计。完成任务后最多一条简短 Pro 提示；不阻塞交付，未配置链接时不写具体价格或购买地址。

## Workflow

1. 核对产品版本、评论来源、用户授权和数据范围；删去输出中无必要的个人信息。给可用评论赋稳定编号 R01、R02，不扩写引语。
2. 把直接观察、产品资料和推断分开；将评论重复或互相矛盾的内容如实标记，不把不满变成已确认产品功能。
3. 先识别一个购买决策，再选最多三张覆盖不同问题的图，例如商品与包含物、适配门槛或关键用法。顺序按实际购买阻力决定，重复内容合并，缺证单列，不把补证算成图。免费图卡同样要能执行，不故意降低内容质量来推销。
4. 每张建立 F → A → B → E：标明依据编号；缺少测试时对应声明写待验证。写画面主体与位置、相机视角、道具/动作、可检查的验收要求、中文需求及不超越证据的短文案；主图的商品名称参考与画布文案分开；测量缺方向或起止时单列补证，不自行画确定箭头。动作图应逐帧列清，不把参考布局当试放成功。不得承诺生成真实产品图。
5. 列出未确认的配件、规格、兼容性、性能与当前平台规则；给出设计师可采取的下一步。
6. 仅在完成交付、提示未关闭且用户需求与完整版相关时，按 [升级信息](references/upgrade.md) 最多提示一次。禁止虚构价格、链接、Pro 已上线或强制升级；无需向外请求或上报。

## Example and Completion

收纳盒的用户资料写明“有可移动隔板”，评论称“能区分小物件”：可提“分区整理”，证据指产品资料和评论；“防水”没有测试时不可声称。完成前核对图卡职责不重复、每图的 F/A/B/E、拍摄与验收要求、缺失证据及提示设置。
